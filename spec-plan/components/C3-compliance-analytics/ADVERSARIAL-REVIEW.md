# C3 — Compliance Analytics Engine — ADVERSARIAL REVIEW

**Reviewer persona:** detection-engineering skeptic + SRE who has muted a thousand noisy alerts + an adversary trying to evade detection.

## 1. The detections will be evaded or fooled
- **A1 — D-BYPASS is blind to events that never reach the K8s audit log.** The whole detector rests on "the K8s API audit event exists even when Gatekeeper's doesn't." But if an attacker can disable/redirect the **API server audit policy** (or operates outside the API server entirely — `kubectl apply` via a compromised controller, etcd write, a static pod), there is *no* K8s-audit event either, and D-BYPASS sees nothing. The platform's headline retrospective detection (HL-06) silently fails against an adversary who removes the audit source rather than just Gatekeeper. **Severity: HIGH.** *Demand:* document that D-BYPASS's completeness is bounded by API-audit completeness; add a *second* independent observation source (runtime scanner inventory — §19.2 step 4 already mentions "runtime scan identifies violating workload") so a workload with neither an admission decision *nor* an audit event is still caught by reconciling the *running* fleet against decisions. Without the runtime-inventory leg, "did it ever get bypassed" has a hole exactly where a real attacker operates.
- **A2 — D-INCONSISTENT input-equivalence hashing is fragile and gameable.** `key(e) = hash(request_object + relevant jwt_claims + external_data_refs)` — "relevant" claims is doing enormous undefined work. Get the relevance set wrong (include a volatile field like a timestamp annotation) and *every* event is its own class → zero divergence ever detected. Include too little and unrelated events collide → false divergence. **Severity: HIGH.** *Demand:* the equivalence relation MUST be derived from the policy-dependency catalog (same source C2 uses for completeness), not hand-tuned per detector, and must canonicalize out non-semantic fields. This is a shared dependency on the catalog whose staleness is already a CRITICAL C2 defect (C2-A1).

## 2. Threshold and noise problems
- **A3 — Every threshold is a false-positive/negative knob with no stated default basis.** `omit_rate > 5%`, `unpaired_rate > 1%` — where do these come from? A 5% JWT-omit threshold means a realm change affecting 4% of tokens (DT-31 said 18%, but a subtler regression could sit at 4%) is *silently tolerated* — a real enforcement degradation under the radar. **Severity: MEDIUM.** *Demand:* thresholds need a documented rationale and SHOULD be anomaly-relative (alert on a *change* from baseline) not just absolute, so a slow creep is caught. A static threshold is an attacker's safe operating margin.
- **A4 — Symptom+cause double-emit (D-C3-03) doubles alert volume.** Emitting both `inconsistent_enforcement` and `policy_drift` for one root cause is defensible for traceability but operationally doubles findings; with eight detectors and per-scope fan-out, an operator drowns. **Severity: MEDIUM.** *Demand:* findings must roll up to a single actionable incident (parent finding) with the symptom/cause as children, or the noise defeats the purpose.

## 3. Determinism claims are overstated
- **A5 — "Re-running a detector reproduces the same findings" (N-C3-4) breaks the moment inputs are late.** C2 ingest latency means the window's events aren't all present when the interval runs; a re-run later (after late events land) produces *different* findings — which contradicts determinism and, worse, means a finding can *appear or disappear* depending on when you look. **Severity: HIGH.** *Demand:* determinism must be stated as "deterministic over a *sealed* window" — a window is only authoritative once C2 confirms no more events for it can arrive (a watermark). Detectors run provisionally on open windows (best-effort, marked provisional) and authoritatively on sealed windows. Without watermarks, the determinism guarantee and the ≤15-min latency guarantee (DT-30) are in direct tension.

## 4. Cross-component contradictions
- **A6 — D-DRIFT's "source-of-truth deployed version" has two candidate owners (A2/B1) and a fallback to "modal observed."** If the SoT store says v12 but the modal observed is v11 (because drift is widespread), the fallback would declare v11 the truth and miss the drift entirely — inverting the detector. **Severity: HIGH.** *Demand:* never fall back to modal-observed for the *expected* version; if SoT is unavailable, emit `policy_drift` subtype `sot_unavailable` (a finding about the pipeline) rather than guessing — guessing here is how a fleet-wide regression hides (HL-12 is exactly a silent regression).
- **A7 — Ownership boundary with C4 is asserted but leaky.** "C3 detects; C4 reconstructs" — but D-BYPASS's *root-cause classification* and *runtime-inventory reconciliation* (A1 above) blur into C4's retrospective-over-a-window territory. Two components scanning for bypasses with different windows will disagree. **Severity: MEDIUM.** *Demand:* the domain index must nail the boundary: C3 = continuous interval detection on the live stream; C4 = on-demand retrospective sweep over an arbitrary historical window; they share the *same* detector library so they cannot diverge.

## 5. Abuse / operational
- **A8 — Findings have a `suppressed` state — an obvious tampering vector.** An insider suppresses the `enforcement_bypass` finding for their own deployment. Is suppression audited? Chained? The spec doesn't say. **Severity: MEDIUM.** *Demand:* finding state changes (esp. `suppressed`) MUST be append-only audit events themselves (chained via C2 primitive), with actor + reason, so suppression is itself evidence.
- **A9 — D-CHAIN depends on C2's verify endpoint, which depends on the signing key C2's own adversarial review flagged as a single point of failure.** If the key is compromised, the attacker re-signs checkpoints and D-CHAIN reports all-green while history is rewritten. C3's integrity detector inherits C2's key-compromise blind spot. **Severity: MEDIUM (inherited).** *Demand:* D-CHAIN must also check the external timestamp/transparency anchor (C2 adversarial D7), not only the platform-signed checkpoint.
